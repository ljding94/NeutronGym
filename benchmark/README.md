# McStasBench — benchmark harness & data

The held-out benchmark slice of NeutronGym: task definitions, the observable-based
grader, and the headless episode runner. **Code lives in `harness/`; everything
else in this folder is data.** Results never land here — every run writes to the
top-level `runs/` (gitignored).

## Layout

| Path | What it is | Committed? |
|---|---|---|
| `harness/` | all benchmark code (see below) | yes |
| `tasks/` | task definitions as JSON, by tier: `P*` pilots/probes, `T1/` reproduce, `T2/` improve-to-target, `T3/` open design; `T1/_validation.json` records self-validation | yes |
| `instruments/` | baseline instruments for T2 tasks (generated by `harness/build_t2_instruments.py`, then committed — they are task inputs) | yes |
| `inventory.json` | the curation registry: machine-verified paper↔`.instr` candidate pool (which references run here, `%Example` agreement, triage notes) | yes |
| `tasks.html` | human-friendly task catalog — generated by `python3 scripts/tasks_report.py`, **never hand-edited** | yes |
| `refcache/` | per-task cached reference-run summaries (the grading ground truth), built on first grade and reused | no — gitignored, regenerable |

## The harness (`harness/`)

Run everything with `conda run -n mcstas python ...` from the repo root.

**Daily drivers:**

- `run_episode.py` — the entry point: one benchmark task → one headless agent
  episode → graded report.
  `python benchmark/harness/run_episode.py benchmark/tasks/T1/T1_PSI_DMC.json
  [--model <alias-or-openrouter-id>] [--no-skill] [--episode-dir DIR]`
  Isolates the episode (fresh `MCSTAS_MCP_HOME` + scratch cwd, skill symlinked
  in), then discovers the instrument the agent actually built, re-runs it under
  the task's env-controlled protocol, and grades it against the cached
  reference. Output: `runs/pilot/<task>__<model>/` with `transcript.jsonl` +
  `report.json` (artifact bundle per the M5 episode-output contract in PLAN.md).
- `grader.py` — grade any `.instr` directly, no agent:
  `python benchmark/harness/grader.py <task.json> --candidate <file.instr> [--params k=v ...]`
- `validate_tasks.py` — curation gate: every task's reference must pass its own
  contract at a fresh seed; T2 baselines must FAIL unimproved.

**Task manufacturing (run in this order when growing the set):**

- `build_inventory.py` — sweep candidate instruments, verify they run here,
  write `inventory.json`.
- `author_tasks.py` — T1 tasks from inventory entries: NL spec-sheet prompts
  derived from the reference + auto-derived grading contracts.
- `build_t2_instruments.py` — generate the parameterized T2 baseline
  instruments into `instruments/`.
- `calibrate_t2.py` — set T2 targets from the constraint-filtered,
  fresh-seed-re-verified classical best (winner's-curse guard lives here).

**One-off probes / measurements:**

- `probe_memorization.py` — contamination probe: can a model reproduce the
  reference `.instr` from memory? (real file ≈1.0 vs from-memory ≈0.07).
- `measure_fast_tier.py` — rollout-throughput measurement (mcrun wrapper vs
  direct binary execution) backing the fast-tier env numbers.

## Grading principles (enforced by the code, summarized here)

Grade the artifact the agent built, never its claims · observable-based checks
(intensity, peak, CoM, FWHM) with statistics-aware tolerances and hard-failure
gating · reference and candidate always compared under the same env-controlled
protocol (ncount + seed set by the task, never by the agent) · any selected
best re-verified at a fresh seed · no LLM judge anywhere in T1/T2.
